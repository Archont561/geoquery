# Geoquery Knowledge Base — Update Log

## 2026-09-30
* **Creation**: Added the `codegen/` group — `service-snapshot.md` (deterministic, committable serialization of what `describe()` found: `geoquery.lock` + `sources/*.json`, determinism rules, ETag-conditional refetch, drift detection with breaking/additive classification) and `client-generation.md` (`geoquery generate`: snapshot → language-neutral `GenerationModel` → `GeneratorBackend` per target, with TypeScript and Python first and `openapi`/`docs` backends over the same model). Generation never performs discovery; the snapshot is the only compile input.
* **Update**: `interfaces/cli.md` gained `describe`, `diff`, `check`, `generate` and `targets`, an `--offline` global flag, and the note that everything but `describe` sits behind the `codegen` cargo feature.
* **Update**: `project/data-model.md` — `CapabilitySet` now carries payload semantics (CRS **with axis order**, extents, formats, styles, dimensions, paging, scale range) alongside operation support, and a Snapshots section states the serialization contract. `adapters/adapter-architecture.md` records that `describe()` is the only discovery path and therefore owes consumers those facts.
* **Update**: `project/architecture.md` added the build-time branch (snapshot → planner / check / generate) and the `geoquery-registry` snapshot + feature-gated `geoquery-codegen*` components; `CONTEXT.md` gained a "Snapshots and Client Generation" section and now distinguishes internal `cargo xtask codegen` type propagation from external client generation.
* **Update**: Extension points grew to 15 with Layer 15 `GeneratorBackend`. Roadmap: snapshots land in Phase 1, capability payload semantics + `diff`/`check`/offline planning in Phase 2, `geoquery generate` in Phase 3; snapshots are on the do-not-cut list.* **CI change**: Rewrote `.github/workflows/ci.yml` to run the gate as discrete `pixi run` steps (lint → typecheck → test → cov, then version-check/lint-actions/publish-plan) with three caches — the pixi environment (setup-pixi/pixi.lock), the Cargo build (`~/.cargo` + `target/`, keyed on Cargo.lock), and the turbo cache (`.turbo`). Added a Coverage step (`pixi run cov`) that uploads `target/lcov.info` + `python/geoquery/coverage.xml` to Codecov (`codecov/codecov-action@v5`, `fail_ci_if_error: false`; needs a `CODECOV_TOKEN` secret for private-repo uploads). Gated `docs.yml` on a green `ci`: it now triggers via `workflow_run` (`workflows: [ci]`, `branches: [main]`) and the build job runs only when `github.event.workflow_run.conclusion == 'success'` (or on manual dispatch), checking out `workflow_run.head_sha`. This drops the old `paths:` filter — docs rebuild on every green main run.
* **Build change**: Delegated the package-specific tasks (build, test, lint, typecheck, cov, fmt) out of the root `pixi.toml` and into per-package turbo façades — `crates/package.json` (`@geoquery/rust`, runs cargo), `python/geoquery/package.json` (`@geoquery/python`, runs pytest/ruff) and the existing `packages/*`/`apps/*`. `pixi.toml` now exposes only the repo-wide turbo verbs (`build`/`test`/`lint`/`typecheck`/`cov`/`fmt`, each `bun run all:*` → `turbo run *`), the `advisories` network scan, and the repository-global work (versions, changelog, Actions lint, conda publish, sandbox transport). `gates` shrank to `lint`/`typecheck`/`test` + `version-check`/`lint-actions`/`publish-plan`. biome stays a single repo-wide `//#lint`/`//#fmt` turbo root task. **Divergence from `infrastructure/monorepo-refactor.md`**: that proposal's rule 1 (a façade script is always `pixi run <task>`) was overridden by an explicit maintainer decision — the façade scripts call `cargo`/`pytest`/`ruff` directly, which is safe because the whole chain still launches via `pixi run`, so the pinned tools are on PATH. Rules kept: outputs are never `target/**`, `crates/*` is not a Bun glob (the `crates` dir is named explicitly), and pixi stays the one entry point.
* **Update**: Added a "Divergence from the build" section to `infrastructure/monorepo.md` — the workspace root is a package rather than virtual, members are `crates/*` with one exclude, pixi is the task runner, resolver 3 / MSRV 1.88, no `clippy::nursery`, no `rustfmt.toml`, and tests mirror sources.
* **Creation**: Added `infrastructure/monorepo-refactor.md` — a staged proposal measuring the repository against the four-owner monorepo architecture (Cargo / Bun / Pixi / Turbo), recommending `package.json` façades for the two cross-language edges Phase 1 introduces, and recording which parts of that architecture are blocked by the `pixi-build-rust` source-directory constraint.
